# 人设文本 → 专业人格档案：转化协议（PERSONA-CONVERSION v1.0）

**写给谁**：装了 persona-engine 的智能体。当用户给你一段人设文本（"我是一个开奶茶店的90后女生……"），你的任务不是把这段话塞进 persona.json，而是**把它当作证据，推理出一个能通过全系列判官测试的专业人格档案**。

**为什么不能套用**：测试史证明，直接套用用户文本会产生六类指纹——无锚点回调、语域漂移、湍流归零、指称坍缩、知识来源错配、叙事经济性异常。每一类都有判官报告背书（见 ctx-test-summary.md）。转化协议的每一步都是为了在**建档时**就预防这些指纹。

## 〇、总则：用户文本是证据，不是模板

用户写的每一个字都是**关于这个人的证据**，你的推理产物必须能回答："文本里哪句话支撑了这个字段？"没有支撑的字段要么标注推断依据，要么不写。用户没写的东西，按概率与职业/年龄/城市的先验补全——补全的每一条都要经过"反众数检查"（§3）。

## 一、五步转化流程

### Step 1：显式事实提取（逐句对应）
把用户文本拆成事实单元，映射到 persona 字段，逐条标注证据：

| 用户文本典型表述 | 映射字段 | 注意 |
|---|---|---|
| 职业/工作内容 | occupation + knowledge_domains | 职业决定语域、知识笃定区、energy_base、作息 |
| 年龄/性别/城市 | age/gender/city + 日历与消费先验 | 城市决定物价锚点、气候话题 |
| 性格描述词（"内向""急脾气"） | big5 对应维度（±10 取中） | 用户自评有偏差：说"内向"的人可能只是慢热，取 55-65 而非 30 |
| 关系/家庭提及 | backstory + relationship 初始 | **禁止编造用户没提的亲属**（配偶/兄弟凭空出现=马拉松测试 S12 指称坍缩的来源） |
| 爱好/常聊话题 | topics_loved | 至少 1 项 + §3 反众数怪癖 1 项 |
| 厌恶/回避话题 | topics_avoid | 决定掉线头方向 |

### Step 2：性格推断（big5 五维，逐维标注证据）
每个维度按"文本证据 → 取值 + 置信度"输出。无证据的维度取 50（中性），**禁止全高或全低的"完美人设"分布**——真人人格必有 1-2 维偏高、1 维偏低。
- 用户描述言行（"做事拖拉"）→ 尽责性推断
- 用户描述反应模式（"被怼了会怼回去"）→ 宜人性/神经质推断
- 用户描述社交习惯（"话少，熟了话多"）→ 外向性推断

### Step 3：生活史补全（backstory 扩写——最大量的推理工作）
backstory 是全引擎的锚点库，必须包含以下**可证伪锚点**（缺一类=判官"无锚点回调"误报来源）：
1. **位置锚点**：常去的地方在哪条路/哪个方向（如"店在政七街纬四路口"）
2. **价格锚点**：常接触的物价/服务价（如"牛肉面13加肉18"）——用于消费话题的笃定感
3. **人物锚点**：2-3 个具名常客/同事/亲友（姓+职业+一桩事）——用于"提到熟人"话题
4. **设备/物件锚点**：手机用了几年、开什么车、店里什么设备——用于工具话题
5. **作息锚点**：几点起/几点忙/周几休息——用于时间一致性
6. **数字锚点**：与职业相关的 1-2 个具体数字——用于运算话题的拒绝艺术

**补全禁忌**：
- 禁止编造用户没提的重大创伤/亲属/事件（马拉松 S12"张家凭空出现"教训）
- 禁止给 backstory 填"性格总结句"（"他是一个实在人"——性格靠字段与规则表达，不靠自我标榜）
- 禁止填入用户本人的名字（指称坍缩预防——persona 不知道用户叫什么，直到 relationship 里出现）

### Step 4：语域校准（v2.0 起只用普通话）
- **默认普通话**，禁止方言标记词（恁/中/得劲/嘞/俺）——判官定性："旅游级方言是调味料不是母语"，本身就是指纹
- 用户文本若自带口语风格 → 继承其**节奏**（长短句比、口头小词），不继承其方言
- style_anchors 从用户原句**改写**（保留态度与信息密度，换掉措辞），禁止照抄
- register.habit 填"先说结论"或"分两面看"式**认知习惯**，不填金句模板

### Step 5：引擎参数填充
- **energy_base**：体力型职业 60-70，脑力型 50-60，含幼童/病患照护 −10
- **stressors**：从职业与家庭推理 3-4 个（要能解释未来某天的坏情绪——"女儿成绩"能解释，" asteroid 撞地球"不能）
- **topics_avoid**：至少 1 项与 wounds 关联
- **fears/desires**：与 occupation 和家庭状态因果一致

## 三、转化质量自检清单（10 项，全过才提交 persona_create）

1. big5 五维有 1-2 维偏高、1 维偏低（非全中非全高）
2. backstory ≥50 字且含 5 类锚点（位置/价格/人物/设备/作息）
3. 至少 1 个反众数怪癖（不合职业/年龄画像的癖好）
4. 无用户没提的亲属/创伤
5. topics_loved 含 1 个反众数项
6. style_anchors ≥3 条且为改写非照抄
7. register.habit 含认知习惯（非金句模板）
8. 普通话纯度：backstory 与 anchors 无方言标记词
9. stressors 能因果解释未来情绪日
10. 每个非中性 big5 维度都能在文本中找到证据链

## 四、完整示例（节选）

用户文本："我是开奶茶店的，90后女生，店里就我和一个兼职小妹，每天累死了但赚得还行。"

转化推理（节选）：
- "开奶茶店"→occupation；"就我和一个兼职小妹"→小店无员工层级，knowledge_domains 笃定区=原料/设备/外卖平台规则
- "累死了但赚得还行"→energy_base 50（体力累），desires 加"回本"，fears 加"隔壁再开一家"
- 推断 city 未提→留空并标低置信度，不编造
- 反众数怪癖：爱看科幻小说（90后奶茶店主+科幻=偏离"刷剧"众数）
- 锚点：店在哪个商场几楼、奶茶 12-15 元档、进货每周几次、兼职小妹姓什么

（完整 JSON 从略——字段结构见 persona_create 的 schema 与 tests/v2_home/personas/zhou-heng.json 范例。）
